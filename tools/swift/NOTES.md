# Swift port notes (SwiftFormat 0.64.7)

## Layout

- `src/swift/token.ts` — token kinds, `SwTokList` (parallel kind/string/aux arrays), Token predicates.
- `src/swift/tokenizer.ts` — `tokenize()`, faithful to Tokenizer.swift.
- `src/swift/formatter.ts` — Formatter: edits, enumeration (`enumStart`/`enumNext` keep
  `forEachToken`'s index right across edits), scope-aware `index(of:after:)` / `lastIndex`,
  auto-updating ranges (`ref`/`unref`).
- `src/swift/parsing.ts`, `parsing2.ts`, `expr.ts`, `funcdecl.ts`, `modifiers.ts`, `decl.ts`,
  `imports.ts` — ParsingHelpers / FormattingHelpers / Declaration ports.
- `src/swift/rule_*.ts`, `rules_*.ts` — the rules.
- `src/swift/guards.ts` — conservative stand-ins for the rules not ported yet (below).
- `src/swift/rules.ts` — rule names in SwiftFormat's order (index by name, then orderAfter).
- `src/swift/dispatch.ts` — generated by `tools/swift/gen_dispatch.py` from `tools/swift/rules.txt`.
- `src/swift/run.ts` — applyRules: trailingSpace+indent first, then every rule, up to 10 passes.

## Options

The CLI with no config infers nothing: `applyRules` only infers shared options that no enabled
rule owns (the sortDeclarations thresholds/locale), and none of those has an inferrer. Swift
version is undefined ("0"), so every `swiftVersion >= X` check is false and `< X` is true:
no if/switch expressions, no implicit self in closures, no trailing commas outside
collections, no implicit returns outside closures, and so on.

Per-rule comparisons with `swiftformat --rules X` differ in one way: with only X enabled, its
shared options (`indent`, `linebreaks`, ...) are inferred from the file. Compare those with
leading whitespace ignored (`LEADWS=1` in the scratch rulecmp script).

## Status

Corpus (`WORK=/work/out-swift bash bench/corpus/cmp.sh <bin> swift`): 5684 / 6710 identical.
Every file that fastfmt formats matches swiftformat byte for byte; the other 1026 are skipped
(left unchanged), almost all because of a guard below.

Timings on the corpus (6710 files): swiftformat 131.7 s wall on 4 cores, 262.5 s with
`taskset -c 0`; fastfmt about 10 s on 4 cores (26 s CPU), 26.2 s with `taskset -c 0 ... -j 1`.

Ported rules: everything in `tools/swift/rules.txt` with a module other than `noop`/`guards`.
No-op rules (`noop`) do nothing with the default options and an undefined Swift version.

Not ported yet, guarded (`src/swift/guards.ts`: the file is skipped when the rule's entry
condition holds, so the guard never changes output, it only gives up):
noForceUnwrapInTests (a `!` in a test case body), swiftTestingTestCaseNames (a `@Test` func
named `test...`), preferForLoop (a multi-line `.forEach` closure), contentBuilder (a
`...Builder` attribute), redundantMemberwiseInit (a top-level struct with one plain-labelled,
non-failable init), redundantEquatable (`Equatable` plus `func ==`), redundantEnumerated
(`for (a, b) in ....enumerated()`), redundantEmptyView (`EmptyView`), redundantSwiftUIGroup
(`Group`). In a 700-file sample they skip, in order: redundantMemberwiseInit 25,
noForceUnwrapInTests 25, redundantEquatable 17, preferForLoop 13, redundantEnumerated 9,
contentBuilder 6, redundantSwiftUIGroup 5, redundantEmptyView 3.

Performance: endOfScope(at:) and the current scope are memoised per mutation count;
replacing a token with an equal one is not a mutation. The next hot spots are
`lastIndexInType` (scope-aware backward scans), `isInStringLiteral` (rebuilt after every edit)
and wrapArguments.

Files with `swiftformat:` directives are skipped. A fatalError in a rule skips the file.

## Known differences

- String.count is approximated (grapheme clusters by scalar classes).
- lowercased/uppercased are ASCII-only (redundantInit's uppercase check included).
- Comment bodies shaped like `word: text` are comment directives to SwiftFormat (nestedIf,
  docComments honour that).
